Governance model

Institutional 4-eye principle and emergency controls.

Dual control (maker-checker). Proposals for material changes are created by one authorized role and approved by a different authorized role. Self-approval is rejected.

RBAC. Roles are enforced at the control-plane API (viewer / proposer / approver / admin). Least privilege by default.

Break-glass. Emergency freeze path exists for severe incidents. Activation is authenticated, reason-coded, and written to the append-only audit chain with notifications.

Full workflow documentation lives in the control-plane docs package (dual-control-workflow, break-glass-protocol, RBAC policies).
